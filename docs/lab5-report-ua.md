# Звіт до лабораторної роботи № 5

## Тема

Робота з файловим сховищем даних, резервним копіюванням, міграціями, імпортом/експортом даних та завантаженням зображень у Fastify API.

## Мета роботи

Реалізувати зберігання даних не в масиві, а у файловій системі, додати атомарний запис, резервне копіювання, міграцію структури даних, імпорт і експорт записів, а також завантаження зображень для об’єктів інвентарю.

## Індивідуальний варіант

Варіант 1 `Inventory`, додаткове поле: `category: string`.

### 2. Створення моделі `src/models/item.model.js`

Створено файл моделі [item.model.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/src/models/item.model.js), який описує повну структуру одного запису інвентарю з дефолтними значеннями:

```js
{
  id: null,
  name: '',
  quantity: 0,
  price: 0,

```

Модель використовується:
- як шаблон для створення нових записів;

Скріншот для звіту:

### 3. Перехід від масиву до файлового репозиторію

Роботу зі статичним масивом замінено на файловий репозиторій [inventory.repository.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/repositories/inventory.repository.js). Кожен об’єкт зберігається окремим JSON-файлом у директорії `data/items/{id}.json`.

Реалізовані методи:
- `findAll` для зчитування всіх файлів з `data/items/`;
- `findById` для читання `data/items/{id}.json`;
- `create` для створення нового запису з використанням шаблону моделі;
- `update` для оновлення існуючого запису;
- `remove` для видалення файлу запису.

Для запису використовується атомарний механізм у [item-files.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/utils/item-files.js):
- спочатку створюється тимчасовий файл `{id}.tmp.json`;
- потім він перейменовується у `{id}.json` через `fs.rename()`.

Враховані виняткові ситуації:
- відсутність каталогу `data/items/` при першому запуску;
- відсутність файлу запису при пошуку або видаленні;
- помилки запису у тимчасовий файл;
- помилки перейменування тимчасового файлу;
- помилки очищення `.tmp`-файлу після невдалого запису.

Скріншот для звіту:
- код репозиторію `repositories/inventory.repository.js`;
- структура папки `data/items/`, де видно окремі файли `1.json`, `2.json` тощо.

### 4. Скрипт `seed.js` для перенесення початкових даних

Створено скрипт [seed.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/src/scripts/seed.js), у який перенесено початковий статичний масив даних. Після цього масив видалено з основного коду застосунку.

У `package.json` додано скрипт:


Під час запуску `npm run seed`:
- очищується поточна директорія `data/items/`;
- створюються нові JSON-файли із початковими даними.

Скріншот для звіту:

### 5. Резервне копіювання при запуску сервера

Реалізовано автоматичний бекап у [backup.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/utils/backup.js). При кожному запуску сервера:
- усі файли з `data/items/` копіюються до `data/backups/{timestamp}/`;
- зберігаються лише 5 останніх резервних копій;
- старіші каталоги автоматично видаляються.

Виклик створення бекапу додано в [app.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/app.js) під час старту сервера.

Скріншот для звіту:
- лог сервера при запуску з повідомленням про створення backup;
- вміст папки `data/backups/`, де видно каталоги з часовими мітками.

### 6. Автоматична міграція структури даних

Створено файл [migrate.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/src/migrations/migrate.js), який:
- обчислює MD5-хеш поточної моделі `src/models/item.model.js`;
- порівнює його зі значенням у `data/version.json`;
- якщо хеші різні, проходить по всіх файлах у `data/items/`;
- додає відсутні поля з дефолтними значеннями моделі;
- перезаписує файли через атомарний запис;
- оновлює `data/version.json`.

У `package.json` додано скрипт:

```json
"migrate": "node src/migrations/migrate.js"
```

У [app.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/app.js) додано перевірку версії моделі при старті сервера. Якщо структура моделі змінилася, сервер не зупиняється, а лише виводить попередження:

```js
fastify.log.warn('Data schema changed. Run "npm run migrate" to update existing files.')
```

Скріншот для звіту:
- термінал після `npm run migrate`;
- файл `data/version.json`;
- фрагмент коду з `app.js`, де виконується `warn` при зміні схеми.

### 8. Експорт даних у CSV

Реалізовано маршрут `GET /items/export` у [inventory.controller.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/controllers/inventory.controller.js). Для генерації CSV використано бібліотеку `csv-stringify`.

Особливості реалізації:
- повертаються всі записи у форматі CSV;
- для поля `image` формується повний абсолютний URL;

### 9. Імпорт даних з файлу

Реалізовано маршрут `POST /items/import` з використанням `@fastify/multipart`.

Підтримуються формати:
- `CSV` через бібліотеку `csv-parse`;
- `JSON` через `JSON.parse()`.

Перед збереженням кожний запис:
- нормалізується;
- перевіряється через JSON Schema;
- або імпортується, або відхиляється з поясненням причини.

У відповіді повертається звіт:
- кількість імпортованих записів;
- кількість відхилених;
- перелік відхилених рядків з номером рядка і причиною.

Скріншот для звіту:
- `POST /items/import` з CSV-файлом;
- `POST /items/import` з JSON-файлом;
- JSON-відповідь зі статистикою `imported`, `rejected`, `rejectedRecords`.

### 10. Завантаження зображення

Реалізовано маршрут `POST /items/:id/image` з використанням `@fastify/multipart`.

Під час завантаження:
- приймаються лише `image/jpeg` та `image/png`;
- максимальний розмір файлу становить 5 MB;
- файл зберігається в `uploads/{id}/`;
- у записі зберігається відносний шлях виду `/{id}/image.jpg` або `/{id}/image.png`;
- при поверненні об’єкта формується повний абсолютний URL до зображення.

Логіку формування повного URL винесено в [item-images.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/utils/item-images.js).

Скріншот для звіту:
- `POST /items/:id/image` у Postman/Bruno з прикріпленим файлом;
- JSON-відповідь сервера з полем `image`;
- відкриття URL зображення в браузері або HTTP-клієнті.

Для видачі завантажених файлів підключено `@fastify/static` у [app.js](/c:/Users/zukov/OneDrive/Desktop/Lab/lab_1/app.js) з кореневою директорією `uploads/`.

Це дозволяє звертатися до зображень напряму за URL, який повертає API.

Скріншот для звіту:

## Висновки

У ході виконання лабораторної роботи № 5 було реалізовано повноцінний файловий механізм зберігання даних замість статичного масиву. Було створено модель об’єкта з дефолтними значеннями, файловий репозиторій з атомарним записом, скрипт ініціалізації початкових даних, систему резервного копіювання та механізм міграції структури файлів при зміні моделі.

Крім цього, застосунок було розширено функціональністю експорту даних у CSV, імпорту записів із CSV та JSON, а також завантаженням зображень із перевіркою типу та розміру файлів. Для зручного доступу до файлів було підключено `@fastify/static`, а для поля `image` реалізовано формування повного абсолютного URL.

У результаті виконання роботи було закріплено практичні навички роботи з файловою системою Node.js, організації резервного копіювання, побудови міграцій даних, роботи з multipart-запитами, CSV-форматами та валідацією даних у серверному застосунку на базі Fastify.
